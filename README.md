# 衡绩 · 员工绩点考核系统

基于 React、TypeScript、Vinext、Cloudflare D1 的完整 Web 应用。源代码、业务规则、数据库迁移和自动化测试均包含在本目录。

## 使用流程

1. 首页默认打开带示例数据的“演示空间”，用于体验，刷新后重置。
2. 登录后点击“进入正式工作区”。正式数据由 D1 数据库持久化，与演示空间和本地预览数据库相互独立。
3. 私有站点的拥有者首次进入正式工作区时自动创建管理员账号。务必完成此初始化后再向其他人开放站点访问。
4. 在“员工与项目组”添加成员，登记他们实际使用的 ChatGPT 登录邮箱。
5. 在“项目库”新建项目，填写合同、可分配经费、项目周期、负责人、组员和系数。
6. 在“月度分配”制定项目月度额度，分配成员当月绩点并保存草稿。可按系数自动分配，再手工调整。
7. 打开已保存的草稿，点击“发布已保存版本”。已发布记录自动计入“绩点报表”，可导出兼容 Excel 的 UTF-8 CSV 明细。
8. 若需调整已发布记录，先撤回再修改并重新发布；日志记录整个过程。

## 已确认的业务口径

- 合同金额区间的单位为**万元**；金额录入最多六位小数，以整数分存储。
- 项目成员系数之和必须为 **1**（100%），百分比可精确至 0.01%。
- 系数 × 合同总额 = 个人合同参考绩点。
- 系数 × 单项目可分配经费 = 个人可分配总额度。
- 可分配经费默认等于合同总额，可在立项时设置为更小的正金额。
- 月度分配率 × 单项目可分配经费 = 当月绩点值；按 1 元 = 1 绩点。
- 个人跨月累计月度分配率不得超过本人项目系数。
- 单项目所有月份、所有人员的累计月度分配率不得超过 1。
- 各月计划额度累计不得超过 1，月度成员分配率之和不得超过当月计划额度。
- 草稿预占额度，只有已发布记录进入员工月度汇总。
- 每人的月度绩点是该月各项目已发布绩点之和。
- 每条绩点先四舍五入到 0.01 再汇总，使用 BigInt 计算乘法以避免浮点乘法误差。若极小金额的舍入会突破月度、项目或个人额度，系统会拒绝并提示调整分配率。

| 合同金额（万元） | 项目负责人参考系数 |
| --- | --- |
| 0 < 金额 < 50 | 0.6–0.9 |
| 50 ≤ 金额 < 500 | 0.3–0.6 |
| 金额 ≥ 500 | 0.1–0.3 |

以上为参考区间，不强制等同硬性上限；超出时必须填写例外说明。

## 权限

- 管理员：维护员工、建立/归档项目、指定负责人、管理全部分配记录与完整报表。
- 项目负责人：维护本人负责项目的成员系数、月度计划与发布；不能转移负责人、管理员工或新建项目。
- 项目成员：查看参与项目、个人月度绩点与个人报表。其他成员邮箱、登录身份标识与非授权项目数据不由接口返回。
- 负责人可查看自己管理的项目分配明细，员工全公司月度报表仅管理员可见。
- 系统使用 Sites 的 ChatGPT 登录。员工邮箱用于首次匹配，由稳定的站点用户 ID 绑定；绑定后不能通过改邮箱转移身份。
- 服务器重新验证每条业务操作；不信任客户端提供的身份或额度。
- POST 请求验证同源 Origin，数据库写入使用 revision 条件原子更新。并发修改时仅一条成功，其他返回 409；界面保留输入，刷新后重新编辑。
- 初始部署为**仅拥有者可访问的私有站点**。团队正式使用前，需要在 Sites 站点分享设置中开放指定同事的访问权限，并在应用员工库登记对应邮箱。本次交付不自动扩大访问范围。

## 数据与实现

`merit_workspace` 表以一个业务聚合保存员工、项目、计划和只追加的操作日志，`revision` 为并发版本号。一次更新同时提交全部额度约束与审计记录，避免跨记录超额竞争。适用于当前版本的中小团队；大型组织部署可在保留规则引擎的前提下拆分规范化关系表。

- `lib/merit.ts`：纯业务规则、权限检查、计算与汇总。
- `app/api/workspace/route.ts`：鉴权、数据可见性、D1 原子更新。
- `app/workspace.tsx`：工作台、项目库、分配、员工、报表、规则和日志。
- `db/schema.ts` / `drizzle/`：数据库结构与迁移。
- `.openai/hosting.json`：站点 ID 与 D1 绑定。
- `tests/merit.test.mjs`：金额边界、权限与分配规则测试。
- `tests/api.integration.mjs`：本地真实数据库的端到端 API 验收。

不提供工资支付、银行转账、OA 审批流或企业单点登录；当前使用 ChatGPT 账号登录。绩点是考核记录，不会触发任何实际付款。

## 本地开发

需要 Node.js ≥ 22.13（推荐 Node 24）和 Git。

```powershell
npm run install:ci
npm run build
# 首次本地启动前按当前生成的迁移文件名执行：
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_living_wallflower.sql
npm run dev
```

开发预览默认 `http://127.0.0.1:5173/`。本机开发模拟登录地址为 `/signin-with-chatgpt?return_to=/`，身份是 `seedy@sites.test`。该模拟仅用于本地开发，不进入正式构建。

本机 npm 的命令垫片存在路径解析问题时，可直接调用正式 npm JavaScript 入口：

```powershell
node 'D:\Soft\nodejs\node_modules\npm\bin\npm-cli.js' run dev
```

自动化检查：

```powershell
node --test --experimental-test-isolation=none tests/merit.test.mjs
node node_modules/typescript/bin/tsc --noEmit --incremental false
```

`node tests/api.integration.mjs` 仅用于没有项目的全新**本地预览**数据库；脚本拒绝非回环地址，验收后删除测试草稿并归档测试项目。不要在已有业务数据的环境运行此脚本。

正式部署由 Sites 应用迁移并提供独立 D1 数据库；本地测试数据和 `.wrangler/` 不上传。运行时认证凭证不写入源码。重要业务上线前应配置数据库备份与组织访问权限。
