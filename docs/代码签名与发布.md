# 衡绩 Windows 代码签名与发布

正式签名需要单位持有的 Windows 代码签名证书。证书私钥不能写入源码、工作区或提交到 Git。

## 所需材料

- 有效的 OV 或 EV Windows 代码签名证书。
- PFX 文件及其密码，或证书服务商提供的硬件令牌/云签名接口。
- 证书主题应与软件发布单位一致。

## PFX 签名构建

在只供发布使用的安全终端中设置临时环境变量：

```powershell
$env:CSC_LINK = 'D:\安全证书\单位代码签名证书.pfx'
$env:CSC_KEY_PASSWORD = '证书密码'
npm run desktop:pack:signed
```

构建完成后立即关闭终端并清除环境变量。不要把证书复制进项目目录。

签名版本输出到 `dist-desktop`。构建命令启用了 `forceCodeSigning`，没有证书或签名失败时不会产生可误发的“已签名版本”。

## 发布前检查

1. 在文件属性的“数字签名”页确认签名者、摘要算法和时间戳有效。
2. 使用 `Get-AuthenticodeSignature` 检查状态为 `Valid`。
3. 计算 SHA-256 并随安装包单独发布。
4. 用一台没有开发环境的 Windows 10/11 电脑测试新建、保存、关闭、重新打开和解密工作区。

未配置证书时可以生成内部测试版，但其发布者身份不能由 Windows 验证。
